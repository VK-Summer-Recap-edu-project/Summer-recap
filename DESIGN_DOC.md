# Диздок

Итак, делаем рекапы. Рекапы, которые захочется репостить, рекапы, которые захочется сохранить как альбом воспоминаний. Нужна интересная статистика, которой хочется делиться. Также мы хотим, чтобы сервис был надежным и точным. Поэтому нужно делать рекапы,“точность" которых можно строго посчитать. Для этого нужно разметить тестовый набор данных и определить метрики.

## Цели на MVP
* Собрать статистику по месяцам для сравнения
* Сбор выводов и статистики в конкретных цифрах
* Создание анимации с исходными фото и цифрами (spotify wrapped style)
* Строгое обоснование качества – нужны метрики и данные каждого модуля
* Асинхронная обработка
* Адаптеры. Проект должен запускаться у комиссии без ключей в сторонние сервисы, поэтому “загрузка через облако/api/другое” должно быть заменено локальной загрузкой тестовых файлов, что удобно реализовать адаптерами.
* Приватность. Файлы не должны передаваться третьим лицам – экспорт идет напрямую к пользователю.

## Доп. цели
* Сравнение лет
* Кастомные визуальные темы и музыка
* Кластеризация на отдельные события и выбор лучших дней

## Чего не будет
* выводов вида “вы провели лето больше с ...”. Все должно быть обезличено.
* “Неизмеримых" выводов. Все выводы должны быть связаны с посчитанными агрегатами. Никаких объяснений картинок ллмками. Делаем упор на надежность.

## Архитектура

### Frontend
* Юзер видит объём выбранной коллекции, прогресс и предупреждения о пропущенных файлах
* Юзер может  указать фото, которые нельзя учитывать для создания рекапа, исключить какие-то фотографии из рекапа и добавить свои
* Смотрит свой рекап и сохраняет без раскрытия доступа третьим лицам

### Backend
* Подгрузка фото выполняется асинхронно, не блокируя интерфейс и сразу в память, не тратя время на запись в диск. Фото грузятся на низком разрешении (какое принимает модель)
* Невалидные файлы не крашат обработку, а помечаются
* Подгрузка фото вынесена в адаптер: мл и фронт ничего не должны знать про то, как файлы грузятся
* Прогресс юзера сохраняется в Redis/Postgres
* Экспорт будет в mp4. После MVP можно будет добавить ссылки

* FastAPI + Pydantic для валидации контрактов, ARQ для воркеров, MoviePy для экспорта.
* Бэк получает запрос на начало: `POST /api/tasks`
* Создает джобу и кладет ее в Redis для ML воркера
* Воркер через адаптер подгружает нужные ему фото
* Воркер обновляет состояния через ARQ когда надо
* При обработке батча (и любом другом обновлении процесса) изменяет состояние, чтобы фронт мог обновить loader

### ML

#### Какие фичи?
* Цвета (статистическое решение)
* Количество снимков (за день, статистическое решение)
* Объекты (векторная форма) (видимо пользователь сам задает название объекта, иначе слишком общий запрос)
* Животные (векторная форма)
* Лица (векторная форма)
* Улыбки (векторная форма)

#### Как их считаем плюс минус?
* Переводим картинки в embeddings с помощью CLIP
* Переводом текст в embeggings с помощью BERT
* Match embeddings (Catboost)
* Получить список фото, подходящих под категорию

#### ML Stack
* Pytorch, PIL/opencv для ресайза картинок. Результаты инференса кладутся в Redis очередь.

## Cross-cutting concerns

### Privacy
Все от загрузки до экспорта приватно – исходные фотографии не должны быть раскрыты

### Observability
Время и качество работы каждого модуля должно быть замерено и задокументировано.

### Robustness
Невалидные файлы ничего не крашат, а помечаются

## Дополнительные сценарии

### Воспоминания
Приложение читает из Облака новые фото, ищет и группирует путешествия или особые события и формирует воспоминания. нужен будет второй адаптер для загрузки. Группировать можно как по локации и сезону (как в apple фотках, там ничего более и нет).
